# 上线清单（Production Readiness）

> 结论：**可以作为「单机本地应用」上线；不能直接作为「联网服务」上线。**
> 标记：✅ 已达标 · ⚠ 需要补 · ⛔ 阻塞项

---

## 0. 一句话结论

把一个只绑 `127.0.0.1`、零鉴权、能读写本机文件系统的服务直接暴露到局域网/公网，等于把这台电脑的文件系统开放给所有人。**本地单机使用没问题；一旦要做「手机/局域网访问」，鉴权必须先做，不能后补。**

---

## 1. 安全

| 项 | 状态 | 说明 |
|---|---|---|
| 监听地址 | ✅ | 只绑 `127.0.0.1:8756`，局域网和公网默认访问不到 |
| 鉴权 | ⛔ | **完全没有**。`/api/fs/list`、`/api/fs/info` 能列目录、查文件信息 |
| 路径约束 | ⚠ | `routes_fs._safe()` 只做存在性/类型校验，允许任意绝对路径（这是「本机路径导入」的功能本身） |
| 上传大小限制 | ⚠ | 未发现显式上限，超大文件会先落盘 |
| CORS | ⚠ | `app.py` 用了 CORSMiddleware，需确认 `allow_origins` 不是 `*` |
| 依赖漏洞 | ⚠ | 未做 `pip-audit` / `safety` |
| 密钥管理 | ✅ | `.env` 未被跟踪；不配 key 也能全本地跑 |

**要做联网版，必须同时具备：** 登录 + 令牌 → 路径白名单（禁止 `/api/fs/*` 访问项目目录以外）→ 请求限流 → 上传上限 → HTTPS。

## 2. 性能（当前最大的体验瓶颈）

| 事实 | 影响 |
|---|---|
| CPU 上 faster-whisper small 约 **0.3–0.6× 实时** | 30 分钟视频要跑 50–100 分钟 |
| 单线程 worker（有意为之，ASR 会吃满 CPU） | 多任务只是排队，不会变快 |
| 音素模型 fp32 约 3GB 常驻 | 8GB 内存的机器偏紧 |
| 首次运行要下载模型 | 第一次「很久没反应」多半是在下模型 |

**必须补的：**
1. UI 显示 **ETA**（`已用时间 / 估计剩余`），而不只是百分比；
2. 明确提示「CPU 识别约为视频时长的 2–3 倍」；
3. 提供更快的档位（`base`/`tiny`）或云端 ASR 作为默认。

## 3. 稳定性

| 项 | 状态 | 说明 |
|---|---|---|
| 任务队列 + 失败日志 | ✅ | `jobs` / `job_logs`，失败可重跑单阶段 |
| 阶段可单独重跑 | ✅ | 按 `force` 重跑，artifact 为契约 |
| 数据库迁移 | ⛔ | **没有迁移框架**，改表只能手动 `ALTER TABLE`；升级新版本的老用户数据可能对不上 |
| 崩溃恢复 | ⚠ | 无「启动时清理僵尸 running 任务」的显式逻辑 |
| 备份 | ✅ | 拆句等破坏性操作会先备份到 `data/backups/` |

**必须补：** `schema_version` 表 + 顺序迁移脚本（这是上线前最容易踩的坑）。

## 优先做（按投入产出比排序）

1. **数据库迁移框架** —— 不加，以后每次改表都是一次数据事故。
2. **ETA + 耗时预期** —— 不改，用户永远觉得「卡住了」。
3. **CI（GitHub Actions）** —— 不改，回归靠自觉。
4. **首次启动引导 + 模型下载进度** —— 决定第一印象。
5. **鉴权 + 路径白名单** —— 只在要做局域网/手机访问时才是阻塞项，但**顺序不能颠倒**。
6. 安装包 + 更新机制 —— 决定能不能给非技术用户用。
