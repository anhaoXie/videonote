# v0.4 设计：统一今日队列 + 按说话人拆句

> 对应 `ROADMAP.md` 的两个 P0。这两件事必须一起做，因为它们动的是同一层：
> **「今天练什么」的编排**，以及**句子的身份（seg_idx）**。
> 先做队列会白做——拆句一跑，队列里所有 seg_idx 都要重映射。

---

## 一、P0-a：单词训练接进 SM-2 复习队列

### 现状（为什么要改）

| 层 | 表 | 调度 |
| --- | --- | --- |
| 句子 | `reviews`（`UNIQUE(project_id, seg_idx)`） | SM-2 ✓ |
| 单词 | `pair_drills`（只记流水） | **无** ✗ |

结果：单词练完就散了，复习页看不到它。而 `README` 里承诺的心智模型是
「**复习队列是唯一的『今天要做什么』**」——单词不在队列里，这个承诺是破的。

### 设计决策

1. **不改造 `reviews` 表，新增 `word_reviews`。**
   `reviews` 的 `UNIQUE(project_id, seg_idx)` 是句子的身份约束；单词没有 project、也没有 seg_idx。
   硬塞进去要么放宽唯一约束（弄脏句子语义），要么加可空列 + 类型判别（SQLite 里全是 null 陷阱）。
   两张表各管一种卡，**统一队列是一层「视图」而不是一张表**——这是最小风险的选择。

2. **卡片粒度 = `(pair_id, word)`，不是 pair。**
   同一个 iː/ɪ 对立里，你可能读得对 `sheep`、读不对 `ship`。按 pair 调度会把这个差异抹掉。
   听音辨词（耳朵）也落到同一个词上——它是对「这个词」的旁证，不是另一张卡。

3. **复用 `srs.schedule()`。** 它本来就是纯函数（吃一个带
   `ease/interval_days/reps/lapses/best_score` 的 dict + 分数），跟「句子」没有任何耦合。
   不重写调度逻辑 = 两种卡的行为永远一致。

4. **入队阈值跟句子对齐（`REVIEW_THRESHOLD = 80`）。**
   跟读读得好、且本来没这张卡 → 不入队（避免队列被一次练对的东西灌满）；
   已有卡 → 每次练习都推进调度（这是「复习」的语义）。

5. **跟读的分数必须体现「关键音」。**
   `routes_words.py` 已经在算 `key_hit`（`/θ/` 那个音到底读对没有）。直接用整词 accuracy 会被
   其它音掩盖——`think` 读成 `sink` 时整词准确率仍有 50%。所以：
   `key_hit ? accuracy : min(accuracy, 40)`，保证关键音错了必然落进「还在学」。

### 混合编排策略

`unified_queue()` 把两张表的今日到期卡合并，按**比率交错**而不是简单拼接：
句子内部保持「逾期越久越靠前」，单词内部同理，然后按 `WORD_RATIO = 1/3` 交替穿插
（约每 2 句夹 1 个词）。理由：单词卡一次只要几秒，纯拼接会让它要么全堆在最前、
要么全被挤到最后；交错才是「热身 → 主练 → 换脑子」的真实节奏。

暴露给前端的每一项都带 `card_type: "sentence" | "word"`，句子项字段**完全不变**
（向后兼容现有 `review.js`）。

### 新接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/words/{wrid}/grade` | 复习页给单词卡打分（听音辨词：正确/错误） |
| POST | `/api/words/reviews/sync` | 把历史练砸的词补进队列（幂等） |
| DELETE | `/api/words/reviews/{wrid}` | 移出队列 |

`/words/say` 与 `/words/listen` 内部改为**同时**写 `pair_drills`（历史流水，保持兼容）
和推进 `word_reviews`（调度）。

### 统计

`analytics.report()` 增加 `words` 段：练了多少词、哪些音最常错、词卡队列计数；
`overview` 的练习次数把 `pair_drills` 也算进去（否则「我今天练了 20 个词」在首页是 0）。

## 二、P0-b：按说话人拆分长句

### 现状

`providers/diarize_local.py` **已经**产出窗口级时间线：

```json
"windows": [{"seg": 3, "start": 12.5, "end": 15.0, "dur": 2.5, "label": "说话人1"}, ...]
```

但 `assignments` 是**按句**按「时长加权投票」压成一个标签（`diarize_local.py:216-218`）。
一句里两个人时，占比大的那个赢，另一个人的话被永久归错。`ROADMAP` 的已知限制 #3 就是这个。

好消息：**不需要重跑声纹模型**。窗口标签已经在 `diarization` artifact 里了。

### 切分算法

```
对每个 segment:
  words = segment.words          # _tidy 合并时 extend 过来的，带词级 start/end
  若 words 为空 -> 不可切，原样保留（诚实降级）
  对每个 word:
      speaker(word) = 与 word 时间区间重叠最长的那个 window 的 label
  把相邻同 speaker 的 word 归成一组 -> 每组 = 一个新的子句
  若只有一组 -> 原样保留
  否则 -> 按子句拆（文本从 words 重新拼，start/end 取首尾词的边界）
```

护栏：

* 子句短于 `MIN_SUB_SECONDS = 0.4` 就并进邻居（切出「Yeah.」这种碎片没有跟读价值）；
* 重叠为 0 的 word（落在两个窗口之间）沿用**前一个** word 的 speaker，不制造第三类；
* pyannote provider 目前不返回 `windows` —— 补上（从 `turns` 直接构造），
  否则换 provider 拆句就静默失效。

### seg_idx 会变，这是这个功能真正的成本

拆句 = 句子列表重排。旧 idx `i` 映射到新区间 `[a_i, b_i]`。所有按 idx 存的东西都要迁移：

| 表/产出 | 有独立时间吗 | 迁移策略 |
| --- | --- | --- |
| `clips` | ✓ `start/end` | 按「与 clip 时间区间重叠最长」挑新句；clip 自己的 start/end/text **不动**（切片文件仍然有效） |
| `scores` | ✗ | 旧 seg_idx → 该区间内**最长**的子句；理由写进 detail |
| `reviews` | ✗ | 同上；若两条旧记录撞到同一个新 idx，**合并**（保留更早的 due、取更高的 best_score） |
| `practice_log` | ✗ | 同上（纯流水，撞了就撞了） |
| `translation` 产出 | ✗（JSON key=idx） | 最长子句拿到译文，其余子句置空；artifact 的 meta 标 `split_stale` |
| `transcript` 产出 | ✗ | 直接用新 segments **重写**（免费，无需 key） |
| `transcript_text`（伪 SRT） | ✗ | 重写 |
| `srt`/`vtt`/`video_hardsub` | ✗ | **删掉 artifact 行**（重新生成是免费的，留着才是错的） |
| `seg_audio/seg_<idx>.mp3` | ✗ | **清空整个缓存目录**——这是最容易漏的 bug：文件还在，但 idx 已经指到别的句子了 |
| `notes`/`summary`/`frames` | — | 不动（不是按 idx 组织的内容） |

### 执行方式：显式任务，不自动跑

拆句会重编号 + 让译文降级，属于「用户该知道自己在做什么」的操作。
所以做成**独立 Stage + 独立 JobKind（`split_speakers`）**，`requires=("audio","transcript","diarization")`，
在界面下拉框里单独可选；不挂在 `diarize` 后面自动执行。

迁移在一个事务里完成，**执行前自动备份数据库**到 `data/backups/`。

## 三、验收标准

1. `tools/test_hybrid_queue.py`：单据 + 单词卡混排、比率正确、SM-2 推进正确、关键音错了必须掉档。
2. `tools/test_split_speakers.py`：合成「A 一句 + B 一句被 ASR 合成一句」，拆句后
   每句说话人正确；同时验证 clips/scores/reviews/translation 的 idx 重映射**没有丢数据**。
3. `tools/test_srs.py` / `tools/test_words.py` / `tools/test_practice.py` 全部仍然通过（回归）。
4. `web/` 复习页能渲染单词卡并录音判分；不选项目时也能看到词卡。
